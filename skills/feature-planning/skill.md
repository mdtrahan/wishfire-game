# Feature Planning

Ground the plan in the current code and the user's requested outcome. Use read-only tools to inspect the relevant implementation, dependencies, and existing checks.

Identify the affected owners, material decisions, dependencies, and evidence needed to call the work complete. Match the detail to the change; a short task may need only a few sentences. Ask for missing information only when it changes scope or a consequential decision that available evidence cannot resolve.

For a planning-only request, deliver the plan and unresolved decisions. If this skill is invoked during an implementation request, use the plan to continue the authorized edits and affected validation rather than ending at a handoff.

For an explicitly requested historical Construct migration, consult [the parity planning reference](references/historical-parity.md). Current gameplay work uses the checkout's live product and ownership contracts.
