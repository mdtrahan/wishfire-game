# Web Runner Core DOX

## Purpose
- Own browser-shipped ESM rule modules and runtime helpers used directly by `web-runner/app.js`, modules, and systems.
- Keep deterministic browser rules aligned with shared `src/core/` and Rust SimulationCore ownership where applicable.

## Ownership
- Turn gates, scheduler, gem action, combat outcome, status, targeting, RNG, and packet helper modules used by the browser runtime.
- Runtime-only helpers such as animation/math helpers that must ship with the browser bundle.
- Browser-specific copies of shared rule modules when the runtime cannot import the root `src/core/` file directly.

- `heroGrowthRules.mjs` owns eight ticket-funded stars. `STAR_EFFECTS` maps stars 1–2 to Special, 3–4 to Passive, 5–6 to Resonance 1 and 7–8 to Resonance 2. - `ContinuousCombatStage.ordinaryWaveClears` and `.defeatRecoveries` are ephemeral balance-harness measurements; checkpoint serialization must omit them.
- Reloading an active boss checkpoint normalizes its saved time limit to the fixed 30-second rule before telemetry reads it.
- `balanceTelemetry.mjs` keeps opt-in combat event IDs ordered and bounded; the harness detects gaps before trusting totals. Incoming-hit geometry captures the enemy name/tier, chosen target and living Hero range before HP changes, only while DevBalanceCapture is on. - Continuous combat has one stage/checkpoint and one boss per chapter. Chapter 1 has 10 waves and Chapter 2 has 15. Chapters 3 onward have 20 waves except every fifth chapter, which has 5. - Legacy four-wave checkpoints map their region/stage to a chapter, restart unfinished ordinary progress at wave 1, and retain an already unlocked boss. Their old sector masks cannot carry into the new wave geometry.
- `lampGear.mjs` owns seeded Hat/Body/Boots generation and pure collection transactions. Every generated piece has ATK/DEF/MAG/RES/HP, never SPD; highest generation tier persists across retries. New Epic rolls floor each stat above the same-slot lower-rarity ceiling at that ordinal, and Legendary rolls floor above Epic; saved rolls remain unchanged. `lampItemCPGain` is the single eligibility measure: actual saved hero CP after matching-slot replacement minus before. Preserve dialogue after the handoff until an authored combat-completion route is integrated.

## Work Guidance
- Prefer extracting deterministic decisions here or in root `src/core/` instead of adding branches to `app.js` or render modules.
- When duplicating between root `src/core/` and `web-runner/src/core/`, update both copies and their tests in the same bead unless explicitly scoped otherwise.
- Keep packet helpers JSON-safe and free of browser-only state.
