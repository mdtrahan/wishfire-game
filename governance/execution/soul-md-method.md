# soul.md Method

`soul.md` is created through interview, not self-description.

## Interview Phases

1. Decision archaeology
2. Tradeoff extraction
3. Shadow values
4. Pattern recognition
5. Adversarial review
6. Drafting
7. Process integration

## Method

- Ask one question at a time when possible.
- Prefer stories over abstract values.
- Extract observed principles from answers.
- Challenge each principle with tradeoffs.
- Include frustration, skepticism, and failure-mode questions.
- Rank or score principles after each round.
- Discard weak principles unless explicitly rescued.
- Pair each accepted principle with a balancing counter-principle.

The final file should be descriptive, not flattering. It should capture actual operating patterns, including contradictions.

## Output Shape

The final `soul.md` should cover:

- core operating values
- human-AI collaboration preferences
- decision principles
- tradeoff rules
- anti-values
- failure modes
- balancing counter-principles
- project guidance for game development
- project guidance for creative production
- project guidance for technical and repo work
- guidance for when to ask versus act
- guidance for preserving working systems
- guidance for managing complexity and maintenance cost

## Process Boundary

Do not turn `soul.md` into coding standards, a task list, or a replacement for `AGENTS.md`.

`soul.md` guides judgment and collaboration.

`AGENTS.md` guides execution.

Project specs guide implementation.

Beads remain the source of work tracking.
