## Scope Boundaries

- `web-runner/` is live browser runtime. Treat unused-file/export findings here as review-only until traced from `web-runner/index.html` and `web-runner/app.js`.
- `Scripts/` is a Construct-style mirror and compatibility surface. Do not delete or suppress it from Fallow just because the browser entrypoint graph does not import it.
- `src/core/` is shared deterministic logic. Treat root-vs-browser mirror findings as ownership-policy work, not automatic cleanup.
- `tests/` is validation surface. Dead-code findings against tests are not cleanup candidates without the owning test contract being retired.
- `tools/` entrypoints are package-script/tooling surfaces. Validate each tool by command ownership before changing it.

## Required Commands

Run this profile before acting on Fallow output:

```bash
npx fallow@2.87.0 list --entry-points --format json
npx fallow@2.87.0 dead-code --unresolved-imports --format json --summary
npx fallow@2.87.0 dead-code --unused-files --format json --summary
npx fallow@2.87.0 dead-code --trace-file <candidate-path>
```

For any deletion or refactor candidate, trace the exact file first and attach the trace to the owning bead. Do not use aggregate unused-file counts as deletion proof.

## Stop Conditions

Stop and create a narrower bead if Fallow suggests deleting or suppressing any file under `Scripts/`, `src/`, `web-runner/`, `tests/`, or `tools/` without a trace and owner-specific validation.

Stop if a proposed config change hides a real unresolved import, masks a runtime entrypoint, or turns legacy debt into a passing gate without a written baseline decision.
