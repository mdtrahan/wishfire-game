Overview

Color pressure becomes build identity.

Wishfire starts with a compact combat verb: pick any three gems of one color. The ability system makes that choice durable through hero ownership, supergem identity spikes, Astral Flow session choices, skill-point ranks, affinity, and Vault/relic pressure.

Player-facing goal: the player should be able to read the board, choose a color, and feel that choice bend toward a recognizable build: ward survival, gold burst, magical field control, support choreography, or long-horizon relic pressure.

Design Scope

This page defines how abilities fit Wishfire.

Use this ability-system slice of the GDD to classify an ability, understand its player purpose, place it in the right lifecycle, and keep mechanics, UI surface, enemy pressure, and playtest expectations aligned as Wishfire grows.

Glossary

Use qualified names. Do not say only "skill."

Term Meaning Common mistake
color action Base result of matching a gem color: attack, heal, Energy, gold, or Astral Flow. Treating a color action as a hero-specific payload.
hero ability Hero-owned combat identity, usually tied to canonical hero skill definitions or native color behavior. Putting a party-wide or Vault passive under one hero because the name feels thematic.
supergem special Native-color identity spike from a larger, rarer gem. Reusing a supergem repair as a live draw skill.
party/session skill Astral Flow draw choice stored in shared session skill state and helping the party until session end. Making it permanent, hero-specific by accident, or counting activation as a payload proc.
skill-point rank Permanent hero skill progress with locked/unlocked state, rank, cost curve, and growth value. Confusing Hero Screen rank progression with Astral Flow session skill selection.
affinity passive Passive identity growth for a hero. It is not a live combat meter. Turning affinity into another draw or proc subsystem.
Vault/relic passive Long-horizon background modifier that depends on Vault/relic foundation design. Implementing it as a live draw card.
proc payload Effect that resolves after activation, eligibility, and roll ownership are satisfied. Letting a dev button or activation text execute the payload.
player evidence Visible result that tells the player what happened: animation, number, icon, log line, modal state, or board change. Letting an ability exist only as hidden state or developer-only output.

Decision Lifetimes

The same idea changes risk when it lasts longer.

Lifetimes are design boundaries. Moving an ability to a longer lifetime changes ownership, tuning, UI, save/reset behavior, and this page's system contract.

Event One resolved action, proc, hit, match, or supergem spend.
Turn Expires after the current actor acts or the turn passes to the other side.
Combat Persists through one encounter until combat exits or resets.
Session / run Astral Flow and selected party skills can shape the current session.
Account progression Skill ranks, affinity, and discovered/equipped relic state may persist beyond a run.
Visual-only Feedback layer only. It must not become gameplay state by accident.

Combat Timing

Resolve ability interactions through named timing stacks.

One linear pipeline is not enough for combat. A new ability must declare which timing stack it enters, what event makes it eligible, and which later hooks it may affect.

Outgoing action Base color action, native supergem replacement, stat query, pre-payload modifier, payload, feedback.
Incoming damage reaction Targeting, intercept, mitigation/guard, shield absorption, true HP damage, reflect/counter, feedback.
Post-damage proc Positive damage or healing gates resolve after payload, then check eligibility, roll, payload, feedback.
Board / refill aftermath Board effects, rerolls, chain pops, refill, and reward hooks resolve after direct combat payloads.
Pre-combat / session passive Affinity, Vault/relic, and session passives enter through explicit setup, stat query, or trigger hooks.
Timing stack Canonical order Skills that depend on it Design risk
Outgoing action Color action -> supergem replace/augment -> stat query -> pre-payload modifier -> payload -> feedback. Bell, Trinity, Growth, Blue Spark, Weaken, Goldstrike. Pre-payload and post-payload procs must not be confused.
Incoming damage reaction Hit declared -> redirect/intercept -> heavy-hit check -> mitigation/guard -> shield absorb -> true HP apply -> post-damage reaction. Temporary Ward, Cover / Block, Phalanx, Reprisal / Bounce, Ward Bash, Guard Rail. Shield-only damage does not count as true HP damage unless the ability says it does.
Post-damage proc Payload lands -> positive amount confirmed -> eligibility -> roll -> secondary payload -> feedback. Destiny, Growth, reward or lifesteal-style future abilities. Activation text or attempted hits must not count as payload evidence.
Board / refill aftermath Match resolves -> board effect eligibility -> bounded reroll/chain effect -> refill -> next action readiness. Second Chance, Chain Pop, Hot Streak, future board-shaping skills. Board effects need no-chain and no-guaranteed-color containment.
Session passive hook Session start or acquisition -> passive registration -> stat query or event hook -> visible proof when it matters. Affinity, Vault/relic passives, Fresh Start, Last Push. Background value must remain inspectable and must not become invisible stat soup.

Skill Draw System

Astral Flow opens a real three-card party-skill draw.

Blue matches fill Astral Flow. When the meter fills, the current hero opens a three-card draw over combat. The player chooses exactly one party-wide session skill, the meter resets to zero, and the selected skill stays active until the session ends.

System part Product contract Current game anchor Must not become
Astral Flow fill Blue play builds toward a session choice, not direct stat inflation. AstralFlowAmpPoints, AstralFlowAmpReady A generic mana bar for every hero skill.
Three-card draw Show three eligible, unique party-skill candidates from canon skill definitions. SkillDrawCandidates Three placeholders or the same first three cards forever.
Selection Activate exactly one session skill, close the modal, and reset Astral Flow to zero. SelectSkillDrawCard A permanent unlock, instant payload, or hidden multi-pick.
Session state Party-wide draw skills live in shared session state and clear on session end/reset. SessionSkillsByHeroUID.__party_shared__ Hero rank storage or account progression.
Card information Target card contract: title, trigger, payoff, chance/rank text, lifetime, risk, and implemented status. Canonical registry plus modal mapping work Flavor-only copy with no trigger, payoff, tier, or lifetime clarity.

Character tier upgrades

Hero skill ranks are a separate character progression system. A tier ladder should read as effective rank values, not vague growth theater. Example: Womble could be "on attack, chance to gain HP" at 3%/6%/9%/12% for ranks 1-4.

Hero Tiered hero skills Rank meaning Draw relationship
Falie Ward Bash, Cover / Block, Reprisal / Bounce, Phalanx Ranks improve protection, retaliation, or anti-spike chance. Not party draw cards unless product canon changes.
Huun Bell, Glare, Trinity, Growth Ranks improve burst, turn delay, extra-action, or damage-to-Flow chance. Can synergize with party draw skills but does not replace them.
Runa Aura Totem: Blast, Aura Totem: Burn, Invert, Intensify Ranks improve green AOE field pressure, burst AOE healing, targeting disruption, damage-profile shifts, or color-payoff amplification. Totem/relic lanes must stay distinct from session party skills.
Kojonn Lock, Lift, Step, Elevate Current ranks improve cost bypass, ally amplification, turn choreography, or amp escalation; redesign may tie him to blue Astral Flow growth. High-risk support or blue-growth ranks need hard anti-loop containment.
Current drift: the current game has the draw state and modal seam, but candidate building still needs real eligible-pool behavior, duplicate policy, implemented-status display, and rank/effective-chance presentation.

Hero Build Tensions

Each hero needs pressure, payoff, and counterpressure.

Chess archetypes come from hero-and-party-skills.md. Use them as skill-shaping pressure, not literal movement rules.

Hero Archetype Skill-shaping use Future skills should Avoid
Falie ROOK Latent potential vs forced destiny. Hold a line through protection, interception, anti-spike defense, and counterpressure. Fragile burst, evasive tricks, or greed mechanics that ignore incoming pressure.
Huun KING Optimization under decay and constant risk calculus. Force clear tradeoffs between cashing out now, holding value, and risking exposure. Safe passive damage, no-counterplay scaling, or unbounded extra-action loops.
Runa KNIGHT Dynamic expansion, rule breaks, and combat-profile pivots. Bend rules through green AOE totems, enemy targeting shifts, hero damage-profile changes, delayed burst, healing bursts, or positional surprise. Generic damage procs that do not change targeting, the board, timing, or combat rules.
Kojonn PAWN Growth through accumulation and eventual transformation. Turn small setup actions into visible Astral Flow acquisition, growth pressure, ally timing, or capstone transformation. Dark-energy identity, cruel black magic framing, invisible aura stacks, or unbounded cost bypass.

Balance Budgets

Risk classes need containment, not adjectives.

Budget class Includes Risk Required containment for high-risk cases Forbidden loop examples
Action economy Extra attacks, repeat actions, free actions High Once-per-event/turn, no self-trigger, no chain recursion. Extra action procs another extra action.
Turn control Advance ally, delay enemy, reorder queue High Cooldown, cap per target, no permanent lockout. Enemy never receives a valid turn.
Sustain Heal, shield, mitigation, cleanse Medium Uptime cap, threshold gating, cannot erase all attrition. Healing fully offsets routine enemy output forever.
Resource conversion Gold to damage, damage to Astral Flow, blue to attack High Conversion cap, decay, no conversion back into its own fuel. Damage creates Flow that creates more damage with no loss.
Board control Reroll, recolor, free gem use, chain pop Medium Limited tiles, limited frequency, no guaranteed desired color loop. Board always stabilizes into one best color.
Stat multiplier 2x attack, amp escalation, stat borrowing High Stack cap, short duration, one source per event. Multiplier stacks with itself before payload resolves.
Persistent hazard DoT, totem, Tainted Ground, detonation charge Medium Duration cap, target cap, enemy counterpressure. Hazard uptime crowds out direct combat choices.
Reward economy Extra gold, drops, chest meter, reward bonus Medium Reward cap, source tagging, no recursive payout. Reward bonus creates resources that retrigger reward bonus.

Ability Spec

A new ability is real only when its play shape is defined.

This is the GDD minimum for adding an ability to Wishfire. It defines what the player can understand, what state the game must remember, and what design limits keep the ability fair.

Ability action shape

Use action shape to keep different ability front doors from turning into bespoke mechanics. A hero rank, party draw skill, supergem, enemy skill, boss mechanic, combo finisher, totem, proc, or passive can enter from a different surface, but the design question stays the same: what readable player action does it create?

Action layer GDD question Must decide
Player intent What does the player read, choose, or set up? Owner, player verb, tactical question, and enemy pressure.
Trigger + owner When can the ability check, and who gets credit? Canonical event, owner/source, eligible states, rejected states, and current-vs-target runtime status.
Target + payload What receives the effect, and what changes? Selector, payload facet, value/rank axis, and invalid-target fallback.
Bounds + counterpressure Why does it stay fair and interactable? Stack or overwrite policy, cap key, reset boundary, cooldown group, cleanup hook, anti-recursion rule, and enemy counter.
Evidence + handoff How can a designer or player prove it worked, or why it did not? Visible cue, trace/proof field, rejected-state reason, and affected companion docs.

Prototype resolver examples live in human-readable pseudocode and proc QA notes; this page names the gameplay contract, not a runtime API.

Target layer Design purpose Current warning
Front door Hero rank, party draw, supergem, enemy skill, boss mechanic, combo finisher, passive, or field effect. Different surfaces should not create separate bespoke mechanics for the same action shape.
Recipe contract Stable id, event, gates, selector, resolver family, payload facet, bounds, presentation, and proof. Per-skill pseudocode is reference material; it is not permission to add one new function per skill.
Resolver family Shared action shape such as instant status, reaction counter, rhythmic tick, field effect, resource conversion, or board aftermath. Resolver families are design targets until a foundation bead maps or implements them in runtime.

Proof packet Make success, miss, rejection, payload, source tag, and containment reason inspectable. Do not use visual feedback or activation text as proof that a payload resolved.
