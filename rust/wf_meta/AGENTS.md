# Meta rules DOX (wf_meta)

## Purpose
- Rust translation of the JS meta rules (`web-runner/src/core`, `src/core`, `web-runner/systems/wfmCombatConfig.mjs`). The JS is the spec; each module header names its source file.

## Contracts
- Numbers follow JavaScript: f64 everywhere, `jsnum::{imul,to_uint32,round,hypot}` reproduce `Math.imul`, `>>> 0`, `Math.round` and V8's `Math.hypot`; `jsnum::{number,number_or,is_safe_integer}` are `Number(v)`, `Number(v)||d` and `Number.isSafeInteger` over JSON values for save sanitizing. Cast to f32 only where the combat ABI does (through JSON) or where the JS does (`hero::hero_special_cooldown` uses `Math.fround`).
- `tests/oracle.rs` asserts every case in `tests/fixtures/rust-oracle/*.json` (written by `tools/rust_oracle/write_fixtures.mjs` from the real JS modules) exactly. Regenerate fixtures only when the JS spec changes, never to make Rust pass; `serde_json` keeps `float_roundtrip` so parsed fixtures are exact.
- `lamp.rs` is lampGear.mjs + lampConveyor.mjs: the v5 save model (`LampEconomy`, validated on JSON values with the JS error messages, unknown keys kept, item stats insertion-ordered), v1-v4 migrations, item generation, kill-point receipts, Bag upgrades, CP comparisons, auto-equip and disposal; `equipment.rs` is the retired v1 catalog, `equipmentStats`, `isEquipmentUpgrade` and `formatCompactCount`. `tests/lamp.rs` asserts `tests/fixtures/rust-oracle/lamp.json` (tiers, 224 generated items, the real 69-item save's review/auto-equip, validation and migration cases, a scripted conveyor run). Disposal signatures are `js_json` (JSON.stringify shape). Battlefield orbs (ORKA-63bf.20) add `lamp.orbs` (uncollected drops, oldest first, at most `ORB_LIMIT` = 40, validated with the conveyor state), `drop_orb_item` (the conveyor's item roll without its cooldown or 16-entry belt); on a full field it displaces the oldest orb of the lowest rarity, ORKA-63bf.22, and `trim_saved_orbs` applies the same rule to an older oversized save before validation, `collect_orb_items(ids)` (the named orbs in drop order, bounded by `free_slots`), `ORB_DROP_CHANCE` (10% per kill) and `adopt_conveyor_emissions`.
- Bag levels are frozen until hero EXP exists to gate them (owner 2026-11-05, ORKA-63bf.26): `upgrade_lamp` stays for that day but the game no longer calls it. The Bag bar runs on `bag_fill_cost(fills)` (50, +25 per completed bar, ceiling 500; owner-adjustable) and `complete_bag_fill` spends the cost (progress points first, then Essence) and banks one fill in `lamp.bagFills`; level, capacity and rarity odds do not change.
- `progression.rs` is combatProgressionRules.mjs + questMilestones.mjs + the starUp rule of heroGrowthRules.mjs: the `orka.combat_progression.v1` state (`create_state` normalizes any snapshot like `createCombatProgressionState`), the xorshift objective roll, action targets by chapter, milestone candidates/reconcile against the lamp loadouts (primary `<name>#1` falls back to the canonical loadout), presentation and reward previews, `record_event`/`claim_reward`, ticket spends/settles, party training and star-ups. Party members enter as `QuestHero` (instance key, canonical name, level, max level, HP). `tests/progression.rs` replays `tests/fixtures/rust-oracle/progression.json`: state normalization cases, the target table, presentation rows and a 570-step driven session where the JS driver satisfied every objective it was handed (equip, level, training, chapter, ticket flows) and recorded the exact state after each step.
- `lamp::field_drop` and the `*_DROP_*` constants (ORKA-63bf.33, Rust-only, temporary): what a kill drops besides an equipment orb; `lamp::grant_essence` credits a picked-up Essence drop. The client supplies the roll, as it does for `ORB_DROP_CHANCE`.
- `lamp::bank_bag_essence` (ORKA-63bf.32, Rust-only like `complete_bag_fill`): at the end of a Cascade Fill the leftover Essence becomes Bag progress points; `fill_progress` is unchanged by it.
- `hero::special_clock` hard-codes the wf_combat passive refill clocks (Fara 10 s, Hondo and Runa 20 s since ORKA-63bf.30, Kaja 5.65 s); change it with `wf_combat::tuning` and the `hero_progress.json` cooldown cases.
- `hero.rs` also carries the Hero-screen text: resonance scaffolding, `skill_copy` (heroSkillCopy.mjs), `special_range_text`, `format_special_cooldown`, `star_effect` rows.
- `narrative.rs` is narrativeRuntime.mjs + narrativeSceneController.mjs + the sync half of renderNarrativeScene.js over the live opening scene (`wishfireWarpCrossingContent.mjs` as static data; the dialogue framework branch is untouched): scene cursor, presentation (typewriter, pages of two sentences, ordered/black-cover shot transitions, auto reading clock, completion), `render_sync` (what a frame resolves, including the logical hit zones) and `pointer`. Sentence segmentation follows ICU as `Intl.Segmenter` applies it to this content (a period run before a lowercase word or another terminator continues the sentence). `tests/narrative.rs` replays `tests/fixtures/rust-oracle/narrative.json` (every line's pages and reading times, a 205-step scripted playback with taps, auto mode, skip and restart against the real controller/renderer on a pinned clock).
- `stage.rs` owns the continuous stage state, templates, transitions, seeded spawn plan and enemy activation; `wfm_config.rs` builds the encounter JSON the host sends to Rust combat (`to_json()` deserializes into `simulation_core::combat_abi::EncounterConfig`).
- `lamp::collect_orb_items(data, ids, heroes)` (ORKA-63bf.34, owner 2026-11-05, Rust-only) judges each named orb at pickup and returns `OrbPickup`: an item `select_auto_equip_hero` finds a hero for (it raises that hero's CP over the worn piece) is stored while `free_slots` allows and otherwise stays an orb; any other item is dismantled at once for `salvage_value` Essence and uses no slot. An empty hero list stores everything (nothing can be judged). `tests/lamp.rs` covers the bare party, the equipped party, a full Bag and repeat pickups.
